## 2. 玩法

| 主题 | 结论 | 理由 |
|---|---|---|
| 维度 | 2D，俯视 3/4 视角 | 像素风天生是 2D；同屏几百只怪的性能要留给网络和特效 |
| 模式 | 合作 PvE，1–4 人，单人也能完整通关 | 幸存者类的乐趣是「我变强、敌潮倒下」；PvP 要人数和平衡，新游戏撑不起 |
| 一局结构 | 照土豆兄弟：约 20 波，每波 20–60 秒，波间进商店，第 20 波打 Boss，整局 15–20 分钟 | 商店是构筑乐趣，也是联机的天然同步点（中途加入、存档、迁移房主） |
| 战场 | 每章一块场地，面积约屏幕的 2×2 倍，每章一到两个地形机制。**边界是魔气而不是空气墙**（用户提议，2026-11-09）：出了场地边缘就进入魔气带，越往外越慢（一踏进去就明显变慢）、按最大气血的百分比掉血越快，魔气带外沿是硬边界；镜头始终以人物为中心，魔气浓到看不见真正的边。画面上是紫黑翻滚的魔气，和场地之间平滑过渡、没有界线 | 难度来自空间压力；队伍自然聚在一起；房主设备的性能可控；敌人「朝目标直走」的前提不被寻路破坏 |
| 角色 | 基础角色：首发 4 个——哪吒、杨戬、赵公明、云霄；2026-11-11 用户选了主角方案一，加上第五个雷震子（木，见下面「雷震子」一行）。每人一件起手法宝、一个被动天赋、一个击杀充能的神通大招（神通耗尽整条「真气」，用户要求消耗多一些：约 80 次击杀充满） | 神通是每波的爆发点；少而精才能把角色做精、撑起台词 |
| 变异角色 | 「回响化身」：基础角色在某一章里以 Boss 身份出现，打败后解锁；法宝、神通、被动全都不同 | 变异和剧情是一回事；一套美术同时用作 Boss 和可玩角色 |
| 隐藏角色 | 孙悟空，靠秘密条件解锁。剧情解释：榜裂之后时间也乱了，未来的齐天大圣掉进了回响。**秘密条件（用户 11-11 确认）**：通关一次（第三章首领倒下，任意劫）之后，标题页的天上多一道很细的金色裂缝，不提示、不闪，点它放一段过场、解锁；主五行木。细节见下面「孙悟空」一行 | — |
| 选角规则 | 解锁后开局即可选；房间内可选角色以房主的解锁进度为准；同一房间不能选重复角色 | 新人跟着老玩家开房，也能用上完整阵容 |
| 难度 | 每章分「劫一」到「劫五」，通关一档解锁下一档，房主开房时选；怪物强度按人数缩放 | 长期目标；每个人都能找到「刚好够难」的那一档；动态难度会偷走成长感 |
| 章节与波次（用户 2026-11-09 改） | **每章 6 波，第 6 波打首领**，打赢进入下一章；法宝、等级、灵物都不重置。每章第 4 波出精英。每波时长和怪物数量以后再调，测试阶段先短一些（20–40 秒）、方便测试；网址加 `?wave=6` 可以直接从第 6 波前的商店开始（带一大笔灵石） | 20 波太长 |
| 难度曲线 | 开局有压力；构筑成型后进入「割草」段；精英和首领是死亡风险波峰 | 用户在深渊提灯里给过的口径：开局有压力、拿到新技能后缓过来；能通关、有难度 |
| 阵亡 | 倒地化成魂魄（能慢慢移动、不能攻击）；队友在身边站满 3 秒救起；没人救则波末自动复活；全员倒地算失败。单人模式在商店里卖续命道具（九转金丹） | 「冲进怪堆救人」是合作最有戏的时刻；惩罚不至于一人失误就整局结束 |
| 经济 | 灵石和经验全队共享，总量按人数调平；每人一个独立商店（刷新、锁定互不影响）；灵石可以转赠队友；全队同时升级，各自选属性，都点「准备」或倒计时结束就开下一波 | 避免队友抢资源；保住每个人自己的构筑乐趣 |
| 专属法宝（用户定，2026-11-09） | 每个角色有一件**专属法宝**，起手自带、可以升阶；哪吒的专属法宝是乾坤圈。专属法宝不进公共商店 | 角色辨识度来自「专属法宝 + 专属宠物 + 神通」 |
| 法宝不可重复、买同名即升阶（用户定，2026-11-09） | 法宝全部靠商店刷出，**没有直接祭炼的按钮**；同一件法宝不会占两个位置，买到同名法宝就是给手里那件升一阶 | — |
| 法宝的形态与品阶（2026-11-09，用户试玩后改） | 品阶：凡 → 灵 → 仙 → 神。商店里有两种形态：**完整**（正常价；没有就占位，有了就升一阶）和**碎片**（升阶材料，很便宜，只对手里已有的法宝有用，同名三枚升一阶；精英宝箱也掉）。**没有「残缺」**（用户：残缺的意思就是升级用的材料，本身就是凡品）。**器灵**：法宝到仙品后才会刷出，买下升到神品并觉醒质变，每件法宝两个器灵二选一（如乾坤圈「金环分光」一次掷两枚 /「赤焰轮」折返炸火环）；商店里两个器灵并排上架，买下一个、另一个随之下架。同名件按手里那件的品阶定价。专属法宝的同名件、碎片、器灵只在角色本人的商店里刷出 | 用户：可以考虑碎片、器灵 |
| 公共法宝清单（用户定，2026-11-09） | 金、木、水、火、土每行 3 件，共 15 件：**金**：打神鞭（锁定血最厚者从天抽下，对精英 / Boss 翻倍）、斩仙飞刀（敌群里来回穿刺追踪）、化血神刀（血光斩，流血叠层）；**木**：雷公鞭（连锁闪电）、定风珠（旋风聚怪再吹散）、青莲宝色旗（青莲结界：人在里面回血，敌人进来被荆棘刺伤）；**水**：阴阳镜（朝最密处扫光束，减速）、寒冰幡（地面冰棱，冻结）、玄元控水旗（水域：敌人大幅减速并持续受伤）；**火**：火尖枪（直线连刺，贯穿灼烧）、九龙神火罩（周身火罩）、五火七禽扇（扇形火浪，击退点燃）；**土**：番天印（天降砸地，晕眩）、戊己杏黄旗（护盾，破碎时震开周围）、捆仙绳（捆住一串敌人，定身易伤；原著是土行孙的法宝） | 每行一件主攻、一件辅攻或控场、一件偏功能 |
| 五行加成（用户定，2026-11-09） | 同属性 1 / 2 / 3 件：**金** 暴击率 +5% / 暴击伤害 +30% /「斩杀」血量低于 10% 直接斩杀；**木** 连锁与聚怪目标 +1 / 每秒回血 /「生生不息」击杀几率回血；**水** 减速 +20% / 命中几率冻结 /「寒彻」被冻敌人受伤翻倍；**火** 灼烧伤害 +20% / 灼烧可叠加 /「燎原」被烧死的敌人炸开点燃周围；**土** 护体 +2 / 击退 +30% /「不动如山」站定时受伤减半 | 3 件档是质变，鼓励全押一行；1 件档让分散搭配也有收益。**2026-11-12 起（用户提的方向）**：宠物也算一件、加了四件档和异行档（三才 / 四象 / 五行俱全），金、木、土的三件档改成看得出来的质变，见下方「五行联动重做」 |
| 法宝位（用户定，2026-11-09） | **4 个**（含专属法宝，即专属 + 3 件公共法宝）；残缺的也占位；满了只能买已有法宝的同名件与碎片，或先卖掉一件。五行加成的门槛是同属性 **1 / 2 / 3 件**（专属法宝也算）| 公共法宝总共只有十几件，3–4 个位置就够；构筑深度主要靠灵物、功法、宠物进化 |
| 人物升级（用户定，2026-11-09） | 除商店外，人物也会升级，规则同土豆兄弟 | 待定：属性清单 |
| 物品种类（用户要求，2026-11-09） | 不能只有法宝和道具，要有更多类型的物品，避免元素单调 | 待定：具体种类 |
| 专属宠物（用户提议，2026-11-09） | 每个角色有一只专属宠物：**无敌、不造成伤害，只给敌人上减益，而且减益要看得见**（用户试玩后改，见下方「M1 试玩反馈」）。宠物和角色各有升级、变强的路线（局内随等级进化，形态随之变化）。初步设想：哪吒 · 混天绫（「缠缚」减速 + 易伤）、杨戬 · 哮天犬（「破甲」）、孙悟空 · 毫毛猴（「戏弄」：出手变慢、走路乱晃，2026-11-11 定）、赵公明 · 黑虎（「震慑」恐惧）、云霄 · 青鸾（「寒羽」减攻速）。宠物起手就跟着、不用解锁；减益的效果与时长吃「范围」和对应五行亲和；人物第 5、10、15 级各进化一次，每次二选一，外形随之变化。宠物和专属法宝都属于角色的主五行（**用户 2026-11-12 改：宠物固定是和主五行不同的另一行**，见下方「五行联动重做」） | 宠物给每个角色一个额外的辨识度和玩法维度；无敌 + 减益的定位，不和角色本体的输出抢位置 |
| 局外成长 | 以解锁为主（角色、法宝入池、劫数、图鉴；2026-11-12 起角色和一部分法宝 / 道具挂在成就上，见「成就」）；另有一张「修为」图谱（2026-11-12 重做：五层洪荒境界、五条路线、34 节，点满约强 25–30%，见「修为」那一行）；难度按「修为点了一半」来调 | 输了也有收获；有上限才保得住难度；新老玩家同房时差距可控 |

### M1 试玩反馈与新规则（用户边玩边提，2026-11-09 下午）

| 主题 | 结论 |
|---|---|
| 角色主属性 | 每个角色有一个**主五行**。专属法宝和专属宠物都属于主五行（起手就适配），其余法宝自由搭配（**用户 2026-11-12 改：宠物不再属于主五行，固定是另一行**，见「五行联动重做」）。哪吒的主五行是**火**（用户确认，2026-11-09；三昧真火、风火轮、火尖枪的形象）：乾坤圈改为火行，混天绫算火行宠物；开局火行亲和 +10% |
| 五行相生 | 不同五行之间要有搭配、增强。法宝命中会在敌人身上留下自己五行的「印记」（约 2.5 秒，头顶一个小色点）；相生的下一行法宝打中带印记的敌人时触发「相生」，消耗印记、飘出名字：金生水「凝霜」（必定冻结，伤害提高）、水生木「导雷」（雷击伤害提高、多跳）、木生火「引燃」（重度灼烧并引燃身边的敌人）、火生土「熔岩」（伤害提高、晕得更久、身上的灼烧一次烧完）、土生金「淬锋」（必定暴击、暴击伤害更高）。混天绫缠住的敌人也带火行印记（2026-11-12 起混天绫是水行宠物，带水行印记）。哪吒（火）天然的搭配是木生火（木行法宝喂火）和火生土（火喂土行法宝） |
| 宠物（混天绫） | 不打伤害，只上减益，减益要看得见：缠住的敌人减速 50%、受到的伤害 +25% 起（「破绽」），身上一直绑着红绫直到效果结束。主人身边一定范围内有敌人时，混天绫就留在敌群里一群接一群地缠，不是缠一下就飞回来；附近没敌人了才回到人物身后（离人物稍远一点）。移动不能太慢，出手不能太快（约 3 秒缠一次）。进化两条线都是减益：缚龙（先定身、一次多缠两只）、火绫（「引火」：受到的火行伤害更高、灼烧持续翻倍）。画面要更精致 |
| 法宝强度 | 冷却不能太短（包括乾坤圈）：全部拉长、单次伤害相应提高，出手要有分量；攻速加成最多把冷却缩到 60%。**各件法宝的 DPS 要接近，不能差太多**（用机器人逐件、逐品阶测）。2026-11-10 起 `tools/weapon-dps.ts` 量群伤、单体、首领三个场景：同一品阶的群伤在中位数 ±15% 以内，**打首领最强 / 最弱不超过 2 倍**。为此首领战里大印、仙品起的乾坤圈、七禽的火鸟先找首领，火浪推、光束照到首领那么远（不超过下面的效果最远），火罩等首领进罩再放 |
| 攻击距离（用户 2026-11-10 试玩：「各种武器、法宝、宠物的攻击距离不能太大」） | 画面 480×270、镜头以人物为中心：上下只看得到人物上下各约 135 像素、左右各约 240 像素，法宝打的都要在画面里。规则（数值在 `config.REACH`）：**索敌半径 130**——离人物 130 像素以内的敌人才会被选为目标（瞄准、落点、第一跳、追谁都只在这里面挑），不吃范围加成；本来就近的（火尖枪、火罩、血光斩、扇子）照旧按自己够得着的距离找，加成后也不超过 130。**效果最远 145**——乾坤圈飞出（人物走开了就提前折返，悬停的圈被人物拽着走）、枪芒、光束、火浪、火罩、火龙、雷的连跳（含导雷、风雷）、飞刀与火鸟追的下一只、金绳捆的下一只、旋风卷的敌人都不超过离人物 145 像素；伸出去的长度吃范围加成，但加成后也不超过它。**落点处的范围**（大印、震波、鞭痕、旋风、水域的半径）以落点为中心，范围加成对它们最多算 +30%。功法一样：五雷正法只劈 130 以内血最厚的，金刚不坏被远处打中时只反弹给 130 以内的。攻速只缩冷却、不改任何距离；宠物的距离另算。鬼火术士的站位跟着改：原来停在离人物 130–185 像素（法宝够不着），改成 90–125，同屏最多 7 只（原来 10 只） |
| 法宝升阶 | **每次升阶都要看得出变化**：低品阶升阶可以只是范围 / 数量变大；**高品阶必须有质变**；神品再由器灵变一次。另外加入**延时减益和持续伤害**（灼烧、流血、雷印、寒气蔓延，以及地面的火痕 / 地裂 / 寒霜）。逐件的品阶梯度见下表 |
| 特效 | 法宝特效要看得见、更华丽、更精致；**出现和消失都不要太快，动画不要太快**；火尖枪现在的特效太丑，要重画。仍然不画俗气的发光圆圈 |
| 战场掉落 | 对战中偶尔掉落：**乾坤宝匣**（宝箱：随机奖励）、**蟠桃**（回血）、**聚灵符**（磁铁的替代：把场上的灵石全部吸过来） |
| 商店界面 | 底子不透明，不要看见背景、不要虚化；要有设计感，不能是现在这种简洁卡片；「锁定」要明显、点得中 |

法宝的品阶梯度（凡 → 灵 → 仙 → 神）：

| 法宝 | 凡 | 灵（量变） | 仙（质变） | 神（器灵二选一） |
|---|---|---|---|---|
| 乾坤圈（火 · 专属） | 一枚，飞出再折返，命中带轻微灼烧 | 更大、飞得更远 | 飞到身边敌人最密处（首领在附近就飞向首领）悬停旋转片刻，反复绞杀圈里的敌人 | 金环分光（两枚各绞一处）/ 赤焰轮 |
| 火尖枪（火） | 一杆枪刺出再收回，贯穿灼烧 | 两连刺、更长 | 枪芒在地上留下一道火痕，持续灼烧踩过的敌人 | 梨花枪 / 贯日 |
| 九龙神火罩（火） | 周身腾起一圈火罩 | 范围更大 | 火罩笼罩片刻，持续灼烧 | 九龙吐焰 / 焚天 |
| 雷公鞭（木） | 落雷后连跳 | 跳得更多 | 被打中的敌人留下雷印，片刻后再落一道雷 | 雌雄双鞭 / 五雷轰顶 |

## 4. 联机

| 主题 | 结论 | 理由 |

| 非房主掉线 | 他的角色原地托管或无敌待命，房间照常继续，回来接着玩 | — |

联机的模拟层（分支 net-sim，2026-11-10，**暂拟，待评审确认**；数值都在 `src/sim/config.ts` 的 `COOP`，规则在 `src/sim/coop.ts`，人员进出在 `src/sim/roster.ts`，存档在 `src/sim/snapshot.ts`）。人数 = 还在房间里的人（离开的不算；托管、倒地、出局的都算），**只在人数 > 1 时生效，单人完全不变**（`node tools/balance.ts 20` 改前改后逐字相同）：

| 主题 | 暂定 | 理由 |
|---|---|---|
| 倒地救援 ★ | 气血打空（莲花化身、替身符这些保命的先生效）→ 倒地 15 秒：不能动、不能出手（宠物也停着），敌人和首领不再追他、打不到他。队友（托管的机器人也算）站到身边 30 像素内持续 3 秒就扶起来：回三成气血、无敌 1.5 秒；两个人一起扶不更快；扶的人走开，进度按一半的速度回落；**有人在扶时倒计时停住**。15 秒没人扶 → 出局；**这一波打完时还倒着的也出局**。出局的人下一波开始时归队：站到最近的队友身边，气血至少一成（商店里买了回春丹就按满血）、无敌 1 秒。所有人都倒地或出局 → 全队陨落 | 计划文档定的规则；「扶的时候停表」免得扶到一半时间到了白扶；倒在魔焰焚城压进来的边上时身子跟着挪进硬边界，队友才够得着 |
| 出局的人在商店里 | 照常逛、照常要等他按「出战」（出局只管战斗：他下一波开始就归队，商店是他补强的地方）。TASK 原文写的是「出局 / 掉线的人不等」，这里改成只不等掉线托管的和离开的；开关是 `COOP.waitOut`（改成 false 就照原文不等出局的人；界面不给出局的人开商店的话必须改） | 出局已经是惩罚，再把他的商店时间也收走，掉队会越拉越大 |
| 按人数加强 ★ | n 人时敌人气血 ×(1 + 0.6×(n−1))（含精英、首领召出的兵），刷怪数（每秒刷怪、包围那一圈）×(1 + 0.5×(n−1))，首领气血 ×(1 + 0.75×(n−1))（换阶段的门槛按比例跟着变）。精英的只数不变。**包围**：联机时加强后的总数平分给每个活着的人、各围一圈（原来只围第一个人，四个人时五十多只全压在他身上） | 计划文档的倍率。机器人试打（`node tools/coop-balance.ts 10`，2026-11-10）：1–4 人都 10/10 通关、联机几乎没人倒地 —— 倍率可能偏低，M4 统一调。**2026-11-11 M4 数值平衡**：敌人气血 0.6 → 0.9、首领 0.75 → 1.1（刷怪 0.5 不变：刷多了四个人在第 3、4 波就崩），见 `docs/balance/log.md` 第 4 轮 |
| 灵石和经验 | 按上面「经济」一行（全队共享、总量按人数调平）做了：谁捡到一颗灵石，房间里每个人各得 价值 ÷ 刷怪倍率（人多了灵石多几成就分几成，每人进账和单人差不多），经验同样，所以早进来的人一起升级；聚灵丹按各自身上的算；宝匣开出的灵石只给开的人 | 设计文档早已定（TASK 里没写，按设计文档补上）；避免抢灵石 |
| 多人商店 | 每人一个货架（买、刷新、锁定互不影响），各自按「出战」；**在场的人**（没离开、没掉线托管）都按了才开下一波，先按的人看得到谁还没好（`Player.ready`）；按了还能取消（`unready`）。剩下的全在托管时等机器人按。灵石可以转赠队友（`give`，只在商店，最多给自己有的） | 计划文档；转赠是「经济」一行早定的 |
| 中途加入 ★ | 只在商店阶段、房间不满 4 人时；新人拿基础起手（角色的专属法宝凡品、宠物），**灵石给在场的人平均数的六成，等级从 1 开始**（经验共享，很快追上来）；站在第一个活着的人身边；货架当场进货，也要按出战 | TASK 定的；六成是「不白拿一整份，也不至于一件都买不起」 |
| 离开 | 任何阶段都可以：人物从场上消失、不算人数（加强倍率、商店等谁、灵石分给谁跟着变），他的格子留着、编号不变，下一个加入的人复用这一格；正飞向他的灵石改给别人 | 输入、灵石飞向谁、首领的危险物都按人物的编号（= 下标）记，挪下标会乱 |
| 掉线托管 | 非房主掉线：他的人物交给机器人（`bot.botTurn`，房主每帧替他出操作）、受到的伤害减半（挨打和魔气都是），商店里不等他（机器人替他买、替他按）；回来时如果正在商店，把出战清掉让他自己逛 | 计划文档；比「无敌待命」好：队伍不少一个人的输出，也不会白送 |
| 整局存档 | `snapshot(w)` 存成纯数据（能 `JSON.stringify`），`restore(s)` 原样恢复，恢复后接着跑和不中断的逐帧相同（测试逐帧核对，包括首领战、四人倒地救援、迁移）。大小：单人刚开波约 2.4 KB、波中中位约 21 KB；四人刚开波约 8 KB、波中中位约 56 KB（最大约 110 KB，gzip 后 23 KB）。房主每波开打时存一份发给所有人；迁移时新房主从这一份重开这一波，把旧房主标成托管 | 本波开始时的存档本来就是迁移的方案（上面「房主断线」一行）；按结构通用地存，以后加字段不用改存档代码 |

联机的网络层与界面（分支 net-wire，2026-11-10 夜 ~ 11-11，**暂拟，待评审确认**；细节、消息格式、实测数字见 `docs/netcode.md`）：

| 主题 | 暂定 | 理由 |
|---|---|---|
| 大厅 ★ | 标题页加「联机」（第二个按钮）→ 名号（这台设备记住）、「建房」、房间码 +「进房」；房间页显示房间码（四位，去掉 0 / O / 1 / I / L）、分享链接（电脑用 localhost 打开时自动换成局域网地址；可以显示成二维码，手机相机一扫就进房）、名单（角色、准备、房主、掉线），其他人「准备」，房主「开始」（连着的人都准备了才能开，一个人也能开）。网址 `?room=ABCD` 直接进房 | 好友房、点开就进（设计文档「组队」）；样式和设置、致谢同一套卷轴 |
| 选角 | 2026-11-11 起（heroes 分支）房间页有一排「角色」按钮（哪吒、杨戬；zhao、yunxiao 分支起加上赵公明、云霄，四个角色时按钮排成两行两列；雷震子起五个基础角色排成两行三列），**同一房间不能重复**：别人选了的变暗、按不了；两个人同时选了同一个，后进房的自动换成没人选的；房主开局、中途有人进来时再兜一次底（`pickFreeHero`）。角色比人少时才允许重复（四个首发角色都能选了，四人的房间也不会重复）。这台设备记住上次选的。**回响化身按房主的解锁**（2026-11-11 variants 分支起）：房主名单上带着他解锁了的那几位（`MemberMeta.un`），房主没解锁的不列；开局、中途进来时选了房主没解锁的，换成能选的（`allowedHeroes` + `pickFreeHero` 的候选）。**隐藏角色（孙悟空）并进同一套判断**（wukong 分支，暂拟）：`allowedHeroes` 也认隐藏角色的解锁 id，房主解锁了才露出他的按钮、才分得到，没解锁连名字都不露。**按钮只造能选的那几位**（房主换了人就重造），同宽、按列出来的名字里最长的取；多于三个排成两行，**纸跟着放宽到排得下**（回响化身的名字有五个字，原来 25em 的纸上四列按钮伸到纸外面去、「角色」两个字被挤出左边），窗口太窄放宽了也排不下就多排几行；名单里「角色」那一列按内容放宽（「回响云霄」不再被截成「回响云」） | 设计文档「同一房间不能选重复角色」；只有两个角色时四人房没法全不重复 |
| 同步 ★ | 不做帧同步，也先不做设计文档里「敌人本地推演、低频校正」：房主每秒 15 次发世界状态的**差量**（通用编码，模拟层加字段自动同步）和这段时间的事件，其他人画面落后约 100 毫秒、在两份状态之间插值，自己的人物本地预测、收到状态再校正；其他人的操作每秒约 30 次 | 局域网里带宽够（4 人后期压缩后最高约 32 KB/s），通用的差量不用跟着模拟层的改动一起改；推演留到上公网时看情况再做 |
| 压缩 | 中继开 WebSocket 的 permessage-deflate（等级 3），状态压到约三成 | 浏览器原生支持，零代码 |
| 暂停 | 房主打开暂停 = 全房暂停（大家看到「房主暂停了」）；其他人打开暂停只是自己的面板，局照常在打、他的人物原地不动（会提示一句） | 模拟只在房主那里；一个人暂停就停全房会被乱按 |
| 掉线 | 其他人掉线：机器人托管（net-sim 的规则），名字签变银灰、后面跟「托」；关了页面又点链接回来的，**名号对得上就把原来的人物还给他** | 凭据存在标签页里，关了标签页就没了；名号每台设备记着，一般不会撞 |
| 房主掉线 ★ | 关页面 / 刷新：立刻迁给下一个人（按进房顺序）；断网、手机切后台：全房先停，最多约 30 秒（6 秒检测 + 24 秒等待）还没回来就迁；电脑上切到后台 30 秒自动让位。新房主从最近一份存档（这一波开打时或商店打开时）重开这一波，大家看到「接手房主 · 从这一波开始重打」 | 设计文档「房主断线」；关页面就是走了，不用等 |
| 中途加入 | 打着的时候进房：大厅里说「这一局正在打，等到万宝阁就把你加进去」，商店一开就加进来 | net-sim 的规则：只能在商店阶段加 |
| 多人画面 | 队友头顶很小的像素名字签（最多四个字，四种颜色：缃、天青、桃红、葱黄；不发光、不加框）；战斗界面左上那一组下面是队友的小血条；倒地的人侧躺、头上一道细细的扶起进度（不画光圈）；出局、离开的不画；别人的神通不停顿、不闪屏、不出横幅 | 用户口径：不要光圈和框；队友的事别抢自己的打击感 |
| 陨落之后 | 谁按「再战」都行：房主换个种子，大家一起从第一波重开 | 合作游戏，一起重开最自然 |

## 5. 表现

| 主题 | 结论 | 理由 |
|---|---|---|
| 风格 | 优先像素风。如果试画证明像素风撑不起「精致」，改用皮影或剪纸风（部件拼装，用代码做骨骼动画） | 用户的口径：「优先像素风，不一定非要像素风」 |
| 规格 | 以 480×270 渲染，画面按 16:9 尽量铺满窗口（2026-11-10 起不再只取整数倍：原来手机上只用了一半到七成屏幕）——整个场景先 1:1 画进 480×270 的贴图，按整数倍最近邻放大到画布，再由浏览器平滑缩到铺满的大小；角色约 24–28 像素高，普通妖兵 12–20，精英约 32，Boss 64–96；只画朝左和朝右，另一边镜像；画面锁定 16:9，更宽的屏幕两侧用装饰边或延伸背景填充，不多显示战场 | 只画左右是这类游戏的标准做法，省下的工作量花在动画帧上；锁定 16:9 是为了电脑和手机同房时视野公平；先整数倍放大再平滑缩，每个像素一样大、移动时不闪，正好是整数倍时完全 1:1（`src/render/view-fit.ts`） |

### 美术口径（M0 试画中用户逐条给出，2026-11-09）

这些是用户看过试画后的明确要求，后续所有美术都按它来：

- **人物要帅、有高级感。** 少年比例（头身约 1:2.5），脸要凌厉（细长眼、刘海压眉），不要 Q 版、腮红、圆点眼。
- **每个主角都必须要帅，宠物也一样；身体比例要协调**（用户 2026-11-11 试玩后）：「杨戬有点前倾，衣服也不好看」「哮天犬一般是黑的。这个豹子也不像豹子」（豹子指赵公明的黑虎）。照上表「人物与宠物的尺子」画。
- **哪吒的衣服要有红色。** 当前方案：深朱砂上衣配墨色交领、金腰带、墨色裤；混天绫比上衣亮一档，免得两块红粘在一起。
- **哪吒头上要有「啾啾」（发髻）。** 叠髻被否（看起来像两个角）。髻不要放正中间、往脑后挪、小一点。用户在后单髻 / 后双髻 / 圆双髻里**选定后双髻**（2026-11-09，对照图 `docs/m0/hair-choice.png`）：两个 5 像素宽的缠绳丸子坐在脑后。
- **人物身上不要任何光圈。** 包括人物脚下的光照，也包括跟着镜头走、因此看起来围着人物的分档暗角。暗角只能平滑地压四个角。
- **攻击预警是地上的淡红光**（用户 2026-11-10 定，取代原来「只用细线、虚线、小箭头，不画实心色块」的口径）：地上一片淡红（朱砂）的半透明光区，
  **形状就是判定范围**（按人物脚下算：脚下进了红光就会挨打），宽度、长度、半径、扫过的角度都照 `src/sim` 里的判定画；
  更亮的一层红随预警进度推进——直线、车道从起点推到终点，圆从中心往外，横扫沿扫的方向——推满就是出手；
  出现时约 0.15 秒淡入并展开，出手那一瞬整块亮到缃、橘（一两帧），之后还危险的部分保持亮着、攻击走过的地方拖一截淡掉，最后 0.3 秒左右淡出；
  柔边是两个整像素宽的分档变淡（判定边界里面一圈 2/3、外面一圈 1/3），不描边、不画框、不模糊；红光带一点同色的光，暗的魔气里也看得清；
  直线和车道里留一排淡淡的小箭头随推进亮起；很多块叠在一起取最大值，不越叠越深。
  画在地面层（人物、敌人和影子下面）。人物、武器身上仍然不要光圈。画法见 `src/game/warn-fx.ts`。
- **背景不要黑**，底色落在中间调以上。
- **要神话玄幻、修仙的感觉，不是历史考古。** 避免青铜鼎、残旗、兵器堆这类考古语汇；用仙台、阵法、仙剑、灵石、玉碑、莲花灯、符箓、云海、灵光。敌人可以保留殷商残魂的样子。
- **要有史诗感，但要克制。** 背景元素不要大；地面不要像方格本或浴室瓷砖；不要用大面积随机像素铺出没有形状的「一团」（试过的灵草地被否）；不要一像素的细裂缝线条（试过的「榜裂」被否，主线里的榜裂以后换别的表现方式）。

当前场景：悬在云海上的青白玉仙台，砖缝磨平、偶有嵌金线和暗刻回纹；中央是半径约 64 像素的八卦阵法，刻槽嵌金、阵眼发天青光并缓慢呼吸；周围有四根朱漆断柱、四盏白玉石灯，零星的剑冢、灵石、玉碑、漂浮的莲花灯和符箓；空中有灵光和桃花瓣，地面有云影飘过。

### 灵物、符箓、相生、五行档的特效（暂拟，待评审确认，2026-11-12，分支 fxpolish）

## 6. 工程与运营

| 主题 | 结论 | 理由 |
|---|---|---|
| 技术栈 | TypeScript + PixiJS 渲染；游戏模拟是独立的纯 TypeScript 模块，固定步长、带种子的随机数，不依赖渲染和浏览器 API；所有操作都是指令；中继服务用 Node 加 WebSocket；Vite 构建，做成能「添加到主屏幕」的网页（2026-11-11：先只有 manifest 和图标，不做 Service Worker，见下面「添加到主屏幕」一行） | 房主权威、迁移房主、无界面跑机器人调数值，三件事都要求模拟与渲染完全分开；包体小，在微信里秒开 |
| 存档 | 不要账号，进度存在浏览器本地，可以导出存档码或二维码；通关后提示导出，并申请持久化存储 | 零门槛；中继保持无状态、不存用户数据 |
| 商业化 | 完全免费，不收费、不接广告 | 国内网络游戏收费要有版号、实名认证和防沉迷，先不碰；不让广告和付费破坏难度与爽感 |
| 部署 | 先在局域网开发：页面和中继跑在用户的 Mac 上，手机连同一个 Wi-Fi 测试。第一章能玩通前，提醒用户准备国内服务器、域名和 ICP 备案 | 有东西可玩之前，公网不急；备案要几周 |
| 首屏与分包（2026-11-11，暂拟，待评审确认） | 打开页面只下标题页这一层：入口脚本只有标题、设置、致谢（存档那一层还带进来整套模拟，gzip 约 52 KB，可以再省，见 `docs/deploy.md`）；字体只预载标题页那约 200 个字的「首屏子集」（两份共 89 KB）。选角、选劫、修为、联机大厅、战斗（连带 PixiJS）、实验页、过场、特效都按需 `import()`；完整的界面字体在标题页画出来 0.3 秒后、其余在 3.2 秒后（开场动画放完）后台下好。同一份内容比，首屏从约 2398 KB 降到约 206 KB。细节和数字见 `docs/deploy.md`「生产构建与包体积」 | 在微信里秒开；标题页上玩家停留的那几秒正好用来下其余的 |
| 低端手机性能与画质（2026-11-11，暂拟，待评审确认） | 目标：CPU 降速 4–6 倍（模拟低端安卓）时最重的场景稳在 50–60 帧，电脑上画面不变。做法是只换实现、不改样子（世界层改成渲染组、几千颗灵石 / 影子 / 眼光画进粒子层并按镜头裁、逐像素的 Graphics 换成像素缓冲、插入排序、着色器和旋转精灵预先准备好……，数字和逐条的说明见 `docs/perf.md`）。设置里加「**画质**：自动 / 高 / 低」：这台设备自己的、不进存档码；**高**就是原来的画面；**低**只动不影响判断的——画布少放大一档（像素边略软）、魔气里翻滚的烟团不画、成团迸出的装饰粒子少一些、打死 / 命中 / 暴击的修仙版特效同屏上限减半；预警的红光、冻住 / 减速 / 眩晕 / 破甲 / 灼烧这些减益、首领出招、屏幕震动任何档都不减。**自动**：先按高档，打着打着连着掉帧就换低档并记在这台设备上（内存很小的安卓一开始就是低档）；不管哪档，掉帧时装饰粒子再自己往下压、帧率回来放回去（不掉帧的电脑上画面和原来一模一样）。网址加 `?perf` 在画面角上看帧率 | 用户正在手机上试玩；低档的取舍（软一点的像素、少一点的烟和火星）需真机试玩后确定 ★ |
| 添加到主屏幕（2026-11-11，暂拟，待评审确认） | web manifest：名字「封神幸存者：回响」（主屏幕上「封神幸存者」）、全屏、方向不锁（11-11 起 `any`，横竖都能玩）、主题色 `#2c2334`；图标是哪吒待机的第一帧整数倍放大、黛色底（`tools/icons.ts`）。**不做 Service Worker**：游戏还在频繁更新，离线缓存会让玩家拿到旧版本、写错了很难撤回；联机必须在线；「添加到主屏幕」不需要它 | 用户：图标用游戏里现成的像素画放大，不另找 |
| 上线方案（2026-11-11，暂拟，待评审确认） | 一台国内云服务器 + 备案过的域名；docker compose 起中继（只在内网）和 Caddy（自动 HTTPS，或 nginx + 云厂商证书）；页面在 `https://域名/`，联机连 `wss://域名/relay`。中继上线版：来源白名单、反向代理后面按 X-Forwarded-For 认 IP、日志一行一事件且不记用户内容和 IP、SIGTERM 时先通知房里的人再关。更新时静态页的旧版本 assets 留着（正在打的玩家还要按需加载）。部署、更新、看日志、费用和带宽估算、**待确定的事 ★** 都在 `docs/deploy.md` | 这一轮只做准备、不上公网：服务器、域名、备案、主体都待确定 |
| 首次载入与后台预载（2026-11-12，用户「第一次进来得看到下载的进度」「点击回响要一会才能进入」，暂拟，待评审确认） | 第一次打开（没有缓存）时先是一屏载入画面：书法「封神幸存者」、一道像卷轴展开的金线（按首屏各文件的真实字节推进）、一行「初次入阵，正在载入」；0.3 秒内就好了的不出现。标题页一画出来就在后台按「选角 → 完整字体 → 战斗 → 大厅、修为、图鉴」的顺序下，左上角一行「余卷载入中」和一道细金线，全到了淡掉。点「回响」时选角还没到，「回响」笔下一道金线随进度展开，到了再进；选角页不等完整字体，先用系统字、到了换楷书 | 用户要看得到进度、点了不干等；进度必须是真的（按字节），不能是匀速假条。顺序按「最先要用的先下」，带宽集中给它 |
| 全屏按钮（2026-11-12，用户「加一个按钮可以开启全屏，隐藏浏览器的地址栏这些」，暂拟，待评审确认） | 标题页右上角一颗带字的墨痕按钮「全屏」（全屏时是「还原」）；局里手机上暂停小牌左边一块同样的小牌（四角折笔的图标）。支持网页全屏的（电脑、安卓、iPad）点了进 / 出全屏；iPhone 的 Safari 不支持，标题页那颗点开是一张纸条「点分享 → 添加到主屏幕，从主屏幕打开即是全屏」，局里不出小牌；从主屏幕打开的本来就全屏，都不出。设置、暂停里原有的开关保留 | 标题页那颗要显眼（用户要「一个按钮」），局里的小牌不挡战斗 |

## 8. 协作方式

- 每个里程碑先自测：单元测试、机器人试玩，再按电脑和手机两种尺寸截图检查。
- 自测通过后停下来，交给用户：局域网试玩地址、截图或录屏、2–3 个需要凭手感判断的问题。
- 里程碑中途，只在用户必须拍板时才停（剧情走向、角色造型等）。
- 剧情大纲和角色设定先交用户审阅，再做过场。
- 每个里程碑打一个 git 标签。
