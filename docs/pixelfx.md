# pixelfx：评估与接入（2026-11-10；接进战斗 2026-11-11）

> 用户 2026-11-10：「参考下这些 skills，看看能不能用来做特效优化，有必要就安装上这个 skills」「我现在在用 ts 做游戏，要 ts 就能直接用的」
> 「要符合修仙风格，如果有必要就做适当的改造」。这份文档回答：pixelfx 是什么、对这个游戏有什么用、要注意什么、怎么接的、怎么用。
> 动手做特效时按 skill 走：先看项目自己的 `fengshen-pixelfx`（`.agents/skills/fengshen-pixelfx/SKILL.md`），再配合官方的 `pixelfx`。

## 结论

能用，已经接进来了，TypeScript 里直接用：

- 库原样放在 `vendor/pixelfx/`（MIT），加了类型声明；游戏里经 `src/render/pixelfx.ts` 的 `PixelFxLayer` 播放，能现场画（可跟随移动的目标），也能预烘焙成纹理（满场出现的一次性效果几乎不花 CPU）。
- 不直接用库的原配色：一律走 `src/render/pixelfx-xianxia.ts` 的修仙版预设（游戏调色板的色阶、压低的辉光）。形状不合规矩的复制到 `vendor/pixelfx/src/fx/xianxia/` 改造，第一个样例是天雷符（`xianxia/tianlei`）。
- Skill 有两份，都装在项目里：
  - 官方原版 `pixelfx`（用户 2026-11-10 要求用 `npx skills add patch-gg/pixelfx --skill pixelfx` 装的，文件在 `.agents/skills/pixelfx/`，不手改）：通用的做法——找现成的、起稿、渲染、看、改，画笔 API，质量清单。
  - 项目自己的 `fengshen-pixelfx`（`.agents/skills/fengshen-pixelfx/`）：这个游戏的规矩（传统色、压辉光、不要光圈、修仙题材、节奏不要快）、仓库里副本的位置、TypeScript 里的用法、怎么改造成修仙版。两边说法不一样时以它为准。
  - 官方 skill 末尾的「Publish it on Patch」一节（装命令行工具、把游戏公开发布）在这个项目里不适用，除非用户自己明确要求。
- 同一天还装了 PixiJS 官方的 skills（`npx skills add pixijs/pixijs-skills`，共 26 个，内容和游戏用的 PixiJS 8.22.0 同版本）：写 Pixi 代码先看 `pixijs`。
- **2026-11-11 接进了战斗**（分支 feat/fx-wire，`src/game/xfx.ts`）：27 个修仙预设逐个和现在的画面比，比现在好的 12 个接了、换下原来的画法（换章云海 chapterClouds 已由 chapters 分支接好），
  其余的写明了为什么不接（见下面「接进战斗」）。满场 300 只敌人时整帧 JS 没有变慢；开局后台预烘焙 31 份、共约 4 MB 显存。

## 它是什么

- 244 个「用代码画的」像素特效，21 个分类（火、爆炸、水、冰、雷、近战、命中、弹道、出生与消散、奥术、神圣、暗影、状态、自然、天气、界面、拾取、转场、小怪……）。
- 每个特效是一个 JS 文件，每帧往两张缓冲里画：color（像素：不透明、抖动、真半透明）和 light（叠加的辉光）。没有图片，所以能换色、镜像、换种子（同一个特效的不同变体）、调大小，输出是确定的。
- 附带工具（只用 Node 自带模块）：连拍图渲染、检查（画出界、没收干净、循环接缝、随机没用种子、单帧太慢）、搜索、起稿模板、导出精灵图集。
- 附带一套做特效的方法（Sprite Fusion 的 Hugo Duprez 总结的）：一句话定方向 → 找参照 → 起几个稿 → 渲染、看、挑毛病、改，至少三轮 → 检查。还有一张「看到什么 → 怎么改」的质量清单。

## 对这个游戏有什么用

1. **现成的效果多，换色就能贴合传统色。** 雷、火、冰、烟尘、碎屑、宝箱开启、拾取、出生与消散、状态（灼烧、冰冻、中毒、眩晕、减速、诅咒……）、转场、天气，正好覆盖法宝、命中、掉落、敌人消散、章节转场这些地方。
2. **方法和质量清单对得上用户的口径。** 「精致」「出现和消失都有过程」「不要一闪而过」——它的标准里本来就有：快进慢出、有主帧、有次级运动（火花、烟、碎屑）、一次性的效果要慢慢收干净。
3. **性能。** 预烘焙之后播放只是换贴图；只有要跟随、要循环的才现场画。

## 要注意的地方（和用户口径冲突的）

- **辉光和光圈。** 很多特效自带大范围的辉光、地面的法阵圈、冲击波圆环（比如原版雷击落地前地上有一圈转动的虚线法阵，冰霜新星有一圈冲击波）。用户不要光圈和光晕，所以辉光默认压到 0.35，带圈的要改造。
- **题材。** 神圣、奥术、科幻几个分类偏西式或科幻，要么不用，要么改成修仙的物件（黄符、阵旗、剑气、云纹、莲花）。
- **尺寸。** 有的特效很大（雷击 240×264，差不多和整个画面一样高）。画面是 480×270 像素，人物约 16–24 像素高，要按比例挑或者改小。
- **浅色地面。** 库默认按暗背景设计，辉光在暗处好看；第一章是浅色仙台，浅底上发灰的要换色阶或者再压辉光。原版雷击落雷前会把周围压暗一块，在浅色地面上像一团暗斑，天雷符里默认关掉了（选项 `veil`）。
- **前后两层。** 有的特效分「人物后面」和「人物前面」两层（`drawBack` / `draw`），现在合在一张贴图里，需要人物夹在中间时要拆成两层。

| `src/render/pixelfx-xianxia.ts` | 修仙色阶 `XRAMP`（暗 → 亮）、火花色阶 `XSPARK`（亮 → 暗）、辉光默认值 `LIGHT`、预设 `XFX`。 |

| `tools/pixelfx-lab.html`、`tools/pixelfx-shot.mjs` | 在 Pixi 里按游戏比例轮播预设（`?fx=`、`&raw` 原配色、`&dark` 暗背景、`&baked` 用预烘焙播）；把特效定在某几个时刻截图（`--at`）；`--compare` 逐像素核对预烘焙和现场画。 |
| `.agents/skills/fengshen-pixelfx/SKILL.md` | 项目自己的 skill：游戏对特效的规矩、TypeScript 用法、改造步骤。 |
| `.agents/skills/pixelfx/SKILL.md` | 官方原版 skill，版本记在 `skills-lock.json`。 |

`PixelFxLayer`（`src/render/pixelfx.ts`）：

- `play(mod, opts)` / `playId(id, opts)`：现场画。每帧调特效的 update 和 draw，把 color 和 light 合成成透明底的 RGBA，
  上传到一张 `BufferImageSource`（最近邻、上传时预乘透明度），放在「原点 − `meta.origin`」的位置。`follow` 每帧问一次位置，返回 null 时收尾。
- `playBaked(key, id, opts, at)`：播预先画好的。每一帧裁掉四周的空白、排进一张图集（一个特效一般一张纹理，按 key 缓存，跨局复用），播放只是换贴图，同一个特效的很多份还能合批；收尾时 0.3 秒淡出；`at.flip` 左右镜像。
  马上返回句柄，还没画好的话画好了才开始播，所以要先 `prebake(key, id, opts)` / `prebakeAll([...])`（开局载入、波间整理时调）。
- `update(dt)` 每帧调（命中停顿时传 0 就定住），`clear()` 换波、重开时清场，`bakedStats()` 看图集占了多少显存，`clearBaked()` 清图集。
- 2026-11-11 接战斗时加的（都是可选的）：`new PixelFxLayer(parent, { flat: true })` 不另建容器、精灵直接放进 parent
  （放进 `stage.entities` 就和角色一起按 zIndex 排序：敌人身上的状态、魂散）；`follow` 除了位置还能给 `z`（跟着改 zIndex）和 `flip`（跟着转身）；
  `fadeIn`（预烘焙的开头淡入几秒，循环的状态出现有过程）、`alpha`、`t0`（从第几秒开始放）、`fps`（现场画的每秒最多重画几次，整屏的效果隔帧画）。
- 两种播法的画面一致：`node tools/pixelfx-shot.mjs <预设名> --compare` 在同一时刻各取一次画面逐像素比，一次性的特效完全一样；
  循环的特效从第二圈起会差十来个抖动像素（现场画的时间一直累加再取余，尾数和第一圈不完全一样），看不出来。
  另外，库把半透明抖动的 4×4 网点钉在世界坐标上：现场画的网点不跟着特效走，预烘焙的跟着走，边缘会差几个像素，也看不出来。
- 特效模块用 `import.meta.glob` 按需加载：每个特效单独打成一个小块，用到才下载，不用的不占首包。

预烘焙占多少显存（`node tools/pixelfx.mjs stats`，2026-11-10 量的；「不裁」是每帧存一整张画布的大小）：

| 预设 | 画布 | 帧数 | 图集 | 不裁 | 画一次 |
|---|---|---|---|---|---|
| thunder（天雷符） | 240×264 | 90 | 6.1 MB | 21.8 MB | 约 80–150 毫秒 |
| burning（2026-11-10 起是修仙版 xianxia/burning，只画火苗） | 44×60 | 36 | 0.08 MB | 0.36 MB | 约 3–10 毫秒 |

（接入时的另外两个旧样例 fireTorch、soulPoof 2026-11-11 从 XFX 删掉了，见下面「接进战斗」最后一节。第一批 27 个预设的显存见 `docs/pixelfx-presets.md`。）

小的一次性效果（命中、消散、拾取）一个只占零点几 MB，适合预烘焙。天雷符这种和画面一样高的大特效一个就 6 MB，
同屏又不会很多，现场画更合适（或者只烘焙一种配色）。辉光会把每帧的有效范围撑大，所以带大范围辉光的特效裁不掉多少。

改造样例 `xianxia/tianlei`（天雷符，改自 `lightning/lightning-strike`）：

- 原作的雷击过程保留：下行先导、三次闪击、雷道冷却后从上往下碎落、地裂上窜的电弧、焦痕。
- 地面的法阵圈（一圈转动的虚线、十字刻度、内圈）换成一张 5×11 像素、立在地上的黄符：开头从上方落下插进土里，朱砂符文随蓄雷自下而上逐行亮起，
  蓄满时闪成雷色，雷落的一刻整张符白一下，化成火星和纸灰。符纸也就是落点的预告。
- 大范围的辉光半径约减半、强度压低；落雷前的局部压暗默认关掉（`veil` 可以打开，0–0.5）。
- 预设：`thunder`（金白天雷）、`thunderTeal`（青白天雷）。
- 2026-11-11 颜色收进了调色板：原来约三成不透明像素不在调色板里（雷库 `lightning/_lib` 的焦黑、地裂冷下去的暗红橘黄，文件里写死的尘、灰、石色），
  现在前后两层画完都用 `snapper(GAME)`（`xianxia/_lib.js`）收成最接近的调色板色，画面几乎看不出变化。

照 skill 走（`fengshen-pixelfx` + 官方 `pixelfx`）。最常用的几条：

```bash
node tools/pixelfx.mjs list slash            # 找现成的
node tools/pixelfx.mjs render thunder        # 用修仙配色出连拍图 → scratch/pfx/records/
node tools/pixelfx.mjs check                 # 检查我们改造过的全部
```

```ts
const pfx = new PixelFxLayer(stage.fx);
await prebake('hitSpark', XFX.hitSpark.id, XFX.hitSpark.opts); // 载入时先画好

```

## 接进战斗（2026-11-11，分支 feat/fx-wire）

> 用户口径：特效要显眼、华丽、出现消失有过程、不要一闪而过；但不要光圈、尺寸收着（哪吒约 16×24）。
> 做法：每个预设先在真游戏里和现在的画面比（同一串随机数、摆好同样的人物和敌人、手动时钟一步步推，改动前用 main 的快照），**比现在的好才换**，
> 换了就把旧的那一份去掉、不叠两层；法宝本身的出手（番天印、化血神刀、斩仙飞刀、雷法）调过很多轮、刚按尺寸收过，只在明显更好时才换。

### 怎么接的

- **`src/game/xfx.ts`**（`XianxiaFx`）：按模拟事件放、每帧跟着敌人和人物走、按种类封顶。`feel.ts` 里只有三处：创建、`onEvent`、`update`
  （`update` 放在 `enemyViews.update` 后面、`wfx.update` 前面：身上的状态先定好归谁画）；换下来的旧画法从 `feel.ts` 里删了（命中火星、魂散光点、拾灵石光点、升级光点）。
- **两层**：`ent` 直接放进 `stage.entities`（`PixelFxLayer` 的 `flat`），和角色一起按 y 排序——魂散、身上的状态、宝匣、金莲；
  `top` 在 `stage.fx`，盖在角色上面——命中、暴击、破甲、拾取、蟠桃、聚灵符。
- **全部预烘焙**：开局时后台一个接一个画（每个之间让出主线程），31 份、约 4.0 MB 显存，一共约 160 毫秒（最慢的一份约 14 毫秒；手机慢 4 倍也就是开局头一两秒偶尔掉一帧）。
  魂散按敌人种类各烘一份剪影（`src/render/pixelfx-actor.ts` 的 `FOE_ART`：游戏精灵 → actor），冻结 / 减速 / 眩晕按四种体型各一份。没画好之前照旧用原来的画法。
- **让出原来的画法**（别的模块各加了一个钩子，没接上时一切照旧）：`EnemyViews.onDeath`（被打死的不再闪白压扁，交给魂散；自爆、换波收走的照旧）、
  `WeaponFx.skipStatus`（冰壳不画了；化开时的冰屑照旧）、`WeaponFx.reactFx`（土生金「淬锋」不放金屑小星；飘字照旧）、
  `DropsFx.onLoot`（宝匣的光线和光点、蟠桃和聚灵符的粒子不放了；匣子开盖、桃子化开、符烧成灰、奖励的字照旧）。
  道具那条线的 `relic-fx.ts` 原来给定身符定住的敌人各贴一张 stunSeal，现在所有晕住、定住的都由 xfx 贴，那一份去掉了（不叠两层）。
- **联机**：都走事件和镜像世界里有的字段；升级、悟功法、吃蟠桃画在那个人身上，拾灵石只把本机自己捡的画成修仙版（别人的照旧是光点）。
- **限流**（`XFX_CAP`，同时在播的个数）：魂散 28、命中 10、暴击 6、冻结 24、减速 24、眩晕 20、破甲 8、拾灵石 3、宝匣 3、蟠桃 4、聚灵符 2、金莲每人一朵。
  同一只敌人 0.3 秒内最多一次命中 / 暴击；拾灵石 0.1 秒最多一次、波末收灵（一口气几百颗）不放。满了的照旧用原来的画法（火星、光点），新加的状态（减速、眩晕）满了就不画。

### 性能（2026-11-11 量的）

`scratch/perf.mjs`（量法照 perf-feel）：`?bot&wave=5`，四件神品 / 仙品（乾坤圈、寒冰幡、番天印、斩仙飞刀，暴击 30%），敌人一直补到 300 只，每秒打死七八十只；
预热 5 秒后量 8 秒每一帧 Pixi 时钟 `update` 的耗时（feel.ts 的整帧 + 提交渲染）。Apple M2 Pro，无头 Chromium，真显卡（ANGLE Metal），同时有别的分支在跑。

| | 整帧 JS 平均 | 中位 | 九成 | 九十九 | 帧率 |
|---|---|---|---|---|---|
| 改动前（main） | 2.94–2.98 毫秒 | 2.7 | 3.9–4.1 | 8.6–8.7 | 约 120 |
| 改动后 | 2.82–3.15 毫秒 | 2.6–3.0 | 3.8–4.1 | 4.9–8.5 | 约 120 |
| 改动前，CPU 降速 4 倍 | 13.8–18.5 毫秒 | 11.8–16.7 | 22–29 | 34–54 | 41–70 |
| 改动后，CPU 降速 4 倍 | 9.7–13.2 毫秒 | 8.6–12.9 | 15–19 | 23–32 | 74–94 |

- 没有变慢；降速时还快一点：原来每打死一只放十几粒粒子 + 一个精灵，现在是一个预烘焙的精灵（同屏满 28 个才退回粒子）。
- `XianxiaFx` 自己：`update` 每帧约 0.03–0.04 毫秒，`onEvent` 合计每帧约 0.005 毫秒（降速 4 倍时 0.17 / 0.025）；同屏在播的 30–60 个。
- 软件渲染（SwiftShader）下帧率被显卡卡在 10–20 帧，前后的整帧 JS 中位都是 4.4–5.7 毫秒，分不出差别。
- 手机横屏 844×390：画面缩到 693×390，冰晶、镇魂符、寒气、魂散、金莲都还看得清，不糊成一片。

## 灵物、相生的修仙版（2026-11-12，分支 fxpolish）

用户：「照妖镜等特效都太廉价了」。新做了三个 xianxia 特效，按 kind 出几种，全部预烘焙：

| 文件 | 预设 | 接在哪 |
|---|---|---|
| `xianxia/xiangsheng` | `reactFrost` `reactConduct` `reactIgnite` `reactLava` `reactPierce`、`blaze` `blazeBig` | `xfx.ts`：`WeaponFx.reactFx`（相生；放了就不放 fx.ts 的火星和 reactRing）、新钩子 `WeaponFx.explodeFx`（燎原；碎冰照旧）。同屏上限 `react` 12、`blaze` 10（低画质 6、5） |
| `xianxia/relic-hits` | `stormHit` `jadeDragon` `zhuoLand` | `relic-fx.ts`（风雷羽、九龙玉佩、金刚琢砸中）；高个子的敌人把原点上挪，胸口对上 |
| `xianxia/relic-charm` | `talismanBurn` `talismanBurnLow` `guBite` `incenseCurl` `umbrellaOpen` `drumBeat` | `relic-fx.ts`（定身符 / 引雷符 / 招宝符、噬心蛊、燃魂香、混元伞、夔牛鼓），跟着人物走 |

火苗用手画的三种大小、每种两帧（`xiangsheng.js` 的 `FLAME`）：程序生成的火舌在这个尺寸下是一团锯齿的红点，不如手画的清楚。
照妖镜不走 pixelfx（镜光两头都在动、要跟着人物和那只妖物），在 `src/game/relic-mirror.ts`，逐像素的部分画进 `PixelSurface`。

性能（`scratch/stress.mjs`：`?bot&wave=15&jie=5` 敌人约 60 只，CPU 降速 6 倍，每秒塞 10 次相生、4 次燎原、5 次定颜珠、风雷羽、九龙玉佩，每 4 秒照妖镜、黄符、混元伞，
比一局里的密度高几倍）：整帧 JS 平均改前 4.8 毫秒、改后 5.4 毫秒，九十九分位 8.3–9.5 → 9.5–12.1，帧率都在 118–120。
不塞事件的 `tools/perf-probe.mjs --scenes horde --rates 6`：中位 5.7 / 5.8 毫秒，60 帧，掉帧 1.7–1.8%，分不出差别。
